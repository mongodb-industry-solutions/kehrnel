# DICOM: one engine, one showcase, a connected developer journey

The public experience is expanded in place at `/healthcare/applications/dicom-metadata-playground`. The signed-in workspace remains `/workspace/dicom-workspace`. Both use the Kehrnel DICOM domain and `dicom.tiered_store` contracts; their datasets and authority differ.

## Narratives and responsibilities

| Surface | Audience | Journey | Source of truth |
| --- | --- | --- | --- |
| Public showcase | Sellers, product owners, architects | See real images → ask a useful question → inspect paired study facts → explore rules by class → understand why MongoDB → build | Frozen source-derived release produced by Kehrnel; no customer connection |
| Healthcare builder | Architects | Select medical imaging → activate the DICOM module → inspect dependencies and deployment choices | Existing DICOM blueprint and strategy manifest |
| Connected developer workspace | Developers | Activate → inspect headers → receive/consolidate → select rules → preview/rebuild → compare indexes → publish → query | Selected environment, trusted tenant/center bindings, Kehrnel runtime |
| Python SDK, CLI and HTTP | Implementers | The same operations, schemas, typed errors and query plans without the UI | Kehrnel plugin and manifest |

There is one public showcase. The legacy `/healthcare/dicom` entry redirects to it. Detailed execution controls belong in the authenticated workspace. The standalone Process Lab remains an explanatory harness, not a second public application or a replacement runtime.

## What is executable in this release

Strategy 0.5.0 adds class-aware metadata extraction, rule previews, study-summary publication, bounded retained-header rebuilding, typed Search mapping comparison/request and query compilation/execution. Public artifacts are generated by that code. The public image-filter answers are frozen source-predicate evaluations; their Atlas Search plans are compiled, not represented as live Atlas results. The additional research recipes are compiled examples.

The existing SDK/CLI/HTTP generic operation dispatcher handles the new operations. Deployment must install the compatible Kehrnel package; changing a website does not upgrade a remote runtime.

## Data placement

| Collection/artifact | Purpose and fields | Lifetime |
| --- | --- | --- |
| Primary studies | Original operational fields (`_id`, `dm`, `pi`, `dt`, `se`) plus a bounded `se[].summary`; typed root aliases used by metadata queries | Always available |
| Series routing catalog | Existing compatibility strategy's independent series routing/operational indexes; it is not a second full header repository | Always available where configured |
| Instance catalog | Scoped SOP identity, series/study identity, order, bytes and stable retained-header locator; it can contain inline raw metadata in a small deployment | Policy dependent; locators must survive receipt expiry |
| Reception inbox | Durable bounded source batch, state and recoverable lease | Temporary after safe acceptance; permanent inventory remains the dedup authority |
| Rule compatibility snapshots | Existing immutable bounded playground generations | Compatibility/evaluation; not the new default research source |
| Immutable metadata rules | Scope, predicates, selected fields, facts and budgets; summaries store a compact scoped ruleRef | Retain while referenced |
| Research metadata extension | One document for a selected series, profile/generation and scope, with exceptional fields; joined by trusted tenant/center/study/series keys | Project or retention policy |
| Immutable header bundles | Full extracted DICOM JSON plus ContentIndex when available, grouped under an explicit byte cap; catalog key/checksum/ordinal resolves a record | Retained to rebuild rules |
| DICOM binaries | Original pixels, documents, waveforms and other payloads | Independent binary-receival and storage lifecycle |

Bundles are immutable objects, not a growing file per series. The filesystem, S3 and Azure artifact adapters implement the same stable locator contract. Object storage is accessed directly by catalog locator; it is not searched for each query. Header-derived facts do not replace pixel analysis.

### Main study fields and their meaning

| Field | Type / meaning | Why it exists |
| --- | --- | --- |
| `_id` | DICOM StudyInstanceUID | Existing strategy identity; ownership conflicts fail closed. Global UID uniqueness on a sharded deployment needs explicit validation. |
| `dm`, `pi`, `dt` | Source center, patient identifier, operational study date | Preserve customer compatibility and viewer query contracts. Patient identifiers must be scoped to the issuer/center or linked through the MPI. |
| `tenantId`, `centerId`, `studyUid` | Typed searchable scope/identity aliases | Search filters do not require a join for authorization. They duplicate trusted `_kehrnel` values deliberately. |
| `studyDate` | BSON Date when a valid date is available | Interval filtering; retain source-date quality. A date-only source is a calendar day, not an inferred acquisition instant. |
| `description`, `descriptionNorm` | Source description and normalized text | Full-text/fuzzy Search and escaped anchored native prefixes. Operational corrections remain the ingestion authority. |
| `se[].si`, `mo`, `de`, `ni` | Series UID, modality, description, operational received count | Viewer shape. A summary filtered by a rule must never replace `ni` or `sz`. |
| `se[].summary.schemaVersion` | Extraction shape contract | Reader compatibility |
| `profileHash` | Hash of selected fields, facts, limits and registry version | Explains projection meaning; scope and predicates are also retained in the document's rule contract. |
| `sourceRevision` | Hash of accepted scoped SOPs and canonical header hashes | Distinguishes source changes from rule changes |
| `acceptedSopCount`, `frameContextsProcessed` | Int64 counts for the selected source | Instance and frame counts are different. Neither means the series has closed. |
| `families` | SOP-Class-derived semantic families | An inaccurate modality label cannot activate the wrong class profile. |
| `acquisitionGroups[]` | Complete observed parameter tuples, class and instance/frame context; counts and bounded source witnesses | Prevents cross-instance/frame false combinations. Source examples are not complete membership. |
| `facts[]` | SR measurements, codes, text, segmentation/annotation facts and context references | Preserve each code/value/unit/target relationship. Some SR template interpretation remains unqualified. |
| `contexts[]` | Shared SR image-reference contexts and bounded witnesses | Large repeated target lists need not be copied into every measurement. Exact target membership requires retained detail if witnesses are capped. |
| `coverage`, `quality`, `detail` | Missing/invalid/applicable counts, truncation and filtering-completeness flags | No silent inference of absent data or complete coverage |
| `_kehrnel` | Trusted ownership, storage schema version, metadata contract version and optimistic revision | Runtime conventions and concurrent-update protection |

Empty derived fields are omitted; valid zero and false values are retained. Original headers remain faithful, including source omissions/empty values. Birth dates, anonymization placeholders, issuer identity and timezone handling require quality policies rather than blind string-to-date conversion.

## Rules: configurable meaning, not arbitrary executable code

The domain registry contains 159 candidate concepts across cohort, acquisition, device and derived-object use cases. This is not a requirement to store or index every concept. Each declares a readable name, tag, VR, type, applicability and optional unit. The 199-header sample covers 18 modalities and 25 storage classes, but it cannot establish 95% research coverage.

A rule selects:

- Trusted center and a source scope by modality, SOP Class and date interval.
- Named fields, common study-summary destination or exceptional extension.
- Up to eight source predicates (`present`, `equals`, `gte`, `lte`). These operate within an instance or an unambiguous shared functional group; arbitrary per-frame predicate paths are rejected or require future explicit context rules.
- Class-aware facts and paired parameter grouping, rather than independent distinct arrays.
- Cardinality and byte budgets. Defaults: 64 groups, 128 facts, 96 KiB summary and three source witnesses. If fixed coverage overhead exceeds the budget, preview fails instead of silently dropping provenance.
- Optional semantic-design inspection. No embedding model, vectors or vector indexes are created.

Full parameter tuples can become expensive when they contain volatile per-frame values. Start with the fields required by recurring questions, then measure observed cardinality. A 96 KiB cap is not a target average: at 350 million series it would represent about 34.4 TB of logical summary BSON before replicas/indexes. Measure the actual modality mix and hot/cold distribution.

## Ingestion: exact sequence

1. Validate trusted scope, DICOM UIDs and the bounded studies/instances input.
2. `update_one(..., $setOnInsert, upsert=True)` records a deterministic durable reception batch. A retry reuses it.
3. `find_one` reads the batch by ID and tenant/center scope.
4. `update_one` claims a pending/failed or expired batch with a lease and unique token; another worker gets a typed busy error.
5. `find_one` checks each SOP against permanent inventory. Same content is a retry; changed content/ownership is a conflict requiring a correction policy.
6. The artifact adapter writes bounded immutable header bundles before catalog publication, or preserves inline metadata. Hash/size/ordinal integrity is verified.
7. `update_one(..., $setOnInsert, upsert=True)` writes unique inventory entries; competing ownership/content is checked again.
8. A scoped aggregation selects accepted locators for affected series. The bounded evaluator hydrates those records and applies rules. It rereads the affected series; it is not an incremental billion-record processor.
9. The compatibility processor writes immutable generation rows and publishes their manifest last. The class-aware rebuild operation separately writes the primary study summary using an optimistic revision check; it preserves other series and operational counts.
10. The receipt becomes processed. Permanent inventory persists. New arrivals produce a later snapshot because series remain open.

`dicom_metadata_rebuild_series` reads one selected instance catalog with a scoped match, sort and limit. It resolves each retained record through the same header adapter and previews or publishes the class-aware summary. Above 500 records or the configured BSON bound it rejects the rebuild; it never publishes a truncated source snapshot as complete. Snapshot here means the catalog rows selected by that query, not a closed series or a globally transactional archive snapshot.

## Rule update: exact sequence

1. Define a candidate rule without modifying the published summary.
2. Preview candidates by modality/class/date in the loaded source, inspect exact grouping and per-series BSON.
3. For real history, estimate through the routing catalog and retained-header inventory. Missing legacy headers are unknown, not negative research evidence.
4. Compare required typed Search paths with the current index. Index discovery failures and nonqueryable builds do not count as ready.
5. Explicitly request the union mapping so a new rule does not remove older promoted fields. Index creation/update is asynchronous.
6. Choose a selected series and read its catalog locators. Retrieve retained headers by stable key/ordinal with integrity verification.
7. Compute a candidate summary under the new contract and recorded source revision.
8. Validate budgets, applicability, missing data and correlations. Preview does not write.
9. Publish with an optimistic filter over the previous study metadata and series snapshot. A concurrent change fails and must be re-read/recomputed.
10. Recheck Search readiness and execute qualified queries with explicit bounded-coverage acknowledgment.

Corpus jobs, durable partition checkpoints, delta capture during long rebuilds, generation cutover, rollback and bounded incremental aggregation are the next production work. A few-minute debounce does not establish a closed series; do not use an unknown expected count to declare completion.

## Queries

`dicom_query` preserves basic viewer querying. `dicom_metadata_query` compiles study-first typed filters and supports connected native/Atlas execution when adapters and index mappings are ready. Examples combine modality, manufacturer, SOP Class, study date interval, observed quantity and description. `se` and `acquisitionGroups` use nested `embeddedDocument`; native comparisons preserve nested `$elemMatch`. Both range bounds apply to one scalar/member of a VM array, not different values. Ordered vector components require explicit rules.

Coded measurement queries bind system, code and numeric range in one fact. Full-text annotation search covers labels, concepts and text; it is not semantic vector search. The exceptional extension recipe joins a selected profile/generation by scoped study/series identity and reports a study-series result grain. Routine research does not start from that collection.

The recipe compiler is bounded and explicit, not a general NLP engine. Agentic conversion should select allowed manifest fields/operators, show its plan and reject unsupported questions. Joining MPI demographics or openEHR conditions is a later governed CDR integration; imaging modality/body part/description alone does not establish a diagnosis.

## Validation and rollout

Public releases must verify source identities, licenses and image hashes, extraction-code hashes, BSON budgets and frozen-answer consistency. They must load without a local synthetic service. Developer execution must be tested through SDK/HTTP/CLI, with scope-denial, concurrent publication, readiness and missing-header cases.

Before production, benchmark the historical 12-billion instance locator import separately from the 2.4-billion annual enriched ingest. Measure per-modality averages/tails, group cardinality, B-tree/Search expansion, replicas, object requests and query latency. Candidate instance shard routing should group a series under trusted tenant/center and a distributed series key, with bounded splitting for extreme series. Study shards should support the dominant patient/day/center patterns. No shard key is automatically deployed by this release.

Do not promise 90–95% coverage until a catalog of representative questions and held-out modality/class samples demonstrates it. Remaining gaps are explicit capabilities, not silent guesses.
